# Account Management in ArchivesSpace
*Last Updated 04/13/2026*
## Adding Permissions 

1. Select the Repository you wish to add permissions to from the ‘Select Repository’ drop down menu. Confirm you are in the correct repository by looking at the Repository name next to the gear icon.

2. Open the System menu and select Manage Users. From there you can find the user in the list, the names are in alphabetical order. Once you find your user, select the edit button. 
3. Your URL will now be something like `https://archivesspace.library.yale.edu/users/120/edit` update edit to edit_groups `https://archivesspace.library.yale.edu/users/120/edit_groups`. Alternatively, You can select the gear icon and open ‘Manage User Access’ then select the ‘Edit Groups’ button. However, this list is not in any searchable order which makes finding your user very time consuming, so the url option is suggested for efficiency.
4. Select Permissions by filling in the check boxes. Use one of the default profiles below or add permissions based on what the Repo manager has requested for the user. 
5. Click Update Account to save permission selections. 


## Permissions Profiles 

These are some basic permissions profiles from [Yale ArchivesSpace User Management Policy](policies/aspace_user_management_policy.md). These are the generic permissions to assign based on the users positions unless the repository manager requests otherwise. Certain Repositories might have unique permissions profiles to select rather than individual permissions. If there is any confusion, contact the repository manager. 

### Repository managers internal to the repository 
Repository managers generally have the following permissions within their repository: 
- Assessments – Create, read, update and delete assessment records 
- Create-accessions – Create, read, and update accessions and top containers 
- Create-digital-object – Create, read and update digital objects 
- Create-events – Create, read and update event records 
- Create-resources – Create, read and update resources and top containers 
- Delete-records – Delete records from this repository 
- Import-jobs – Initiate and cancel an import job 
- Manage-top-containers – Delete or bulk update top containers in this repository 
- Merge-records – Merge records from this repository 
- Repository-managers – Manage a repository (manage locations, user groups, department codes, user access) 
- Subject-agent – Create, read, merge, update and delete subject or agent records (affects all repositories) 
- Suppress-records – Suppress records from this repository 
- Transfer-distinct-records – Transfer distinct records across a repository 
- View-records – View (non-suppressed) records in this repository 
- View-suppressed-records – View suppressed records in this repository 
- Vocabulary-classification – Create, read, update and delete vocabulary or classification terms (affects all repositories)

## Deactivating and Deleting Accounts 
Traditionally we only deactivate accounts, deletion is not usually done. 
1. Open the System menu and select Manage Users. From there you can find the user in the list, the names are in alphabetical order. 
2. Select ‘Deactivate’, this will immediately deactivate the account. You can always reactivate the account at any time by selecting ‘Activate’. 
3. If for some reason you do need to delete an account, select ‘Edit’. The top right-hand corner will have a delete button for those with high enough permissions. Click the button to delete the account. (If you are having difficulty doing this, try saving the account then deleting.)
